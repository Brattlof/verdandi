# 0022 · The native harness loop runs on the Anthropic SDK

## Status

Accepted (spike 019 and issue #143, 2026-10-02).

## Context

M4 starts with Verdandi's own agent loop (DESIGN §9.4) on one provider, the Anthropic API in `metered` access mode (§9.5). Every route today is Claude Code, which can't change effort per turn without a cache miss (ADR 0002). The loop has to fit the existing `HarnessAdapter` contract (one `run` per turn, `respond`, `reroute`, `close`, interrupts by fiber interruption) and keep its rules: the system prompt and tool list stay byte-for-byte fixed for a session, turns alternate, thinking blocks go back unchanged.

Two questions needed code, not reading: how the loop maps onto `HarnessAdapter`, and whether to call the Messages API with raw `fetch` and our own SSE parser or with the official `@anthropic-ai/sdk`. Spike 019 ran the SDK (0.125.0, already in `bun.lock` as the Agent SDK's peer) against a scripted fake `fetch`: no network, no key.

What it showed:
- `messages.stream()` streams text deltas, and `finalMessage()` assembles thinking blocks with their signatures, tool inputs from split `input_json_delta`s, and merged usage. `cache_control` (top level and per block), `output_config.effort` and `thinking` pass through unchanged.
- Aborting the request's `signal` raised `APIUserAbortError` in under 1 ms, aborted the fetch, and rejected `finalMessage()`, so no partial assistant message reaches the transcript.
- The SDK retries 408/409/429/5xx with backoff on its own (a 529 then a success took two requests, about 430 ms); with `maxRetries: 0` it raises a typed `APIError` with `status`.
- A prototype loop held an approval on a promise, put a steer after the tool results in the same user message, and on an interrupt answered every open `tool_use` with an error result, so the next request was valid with nothing rewritten. System and tools were byte-identical on all four requests.
- Bun 1.4.2 has `Bun.secrets` (macOS Keychain, libsecret, Windows Credential Manager).

## Decision

1. **Package and id.** `packages/harness-native` implements `HarnessAdapter` with id `native`. `HarnessId` gains `"native"`: widening the literal union keeps every stored event readable.
2. **The SDK, not raw fetch.** The provider is `@anthropic-ai/sdk`, pinned at `0.125.0`, the version the Agent SDK already resolves, so `bun.lock` gains no package. Raw `fetch` would mean owning about 200 lines of SSE parsing, block assembly (text, thinking with signatures, streamed tool input), retries with `retry-after`, typed errors and request types, and keeping them in step with new block types (compaction, fallbacks, server tools). DESIGN §9.5 already names the SDK. There is no internal provider interface until a second provider needs one.
3. **One session per thread.** The adapter keeps a session per thread: its id (a UUID, reported in `session.started`), its transcript, and the system prompt and tool list built when it opened. The transcript is `<home>/native-sessions/<session>.jsonl`: a header line holding that prefix, then one line per message, each tagged with its turn id, only ever appended. After a restart a thread resumes by id with the prefix from the header, so a changed tool list can't reach a running session. A revert's `fork` copies the entries through the end of `atTurnId` into a new session with the same prefix, whose cache it reuses. A missing transcript starts a new session with a `notice` item.
4. **A fixed request prefix.** `tools` is the run's Verdandi tools in `verdandiTools` order, plus the harness's `propose_plan`. `system` is the harness's instructions and the session's folder, with `cache_control` on its last block. Both are built once per session and never change. A top-level `cache_control: { type: "ephemeral" }` moves the second breakpoint along with the conversation. TTL is the default 5 minutes. The model is the route's model. `output_config.effort` is the route's effort, and `thinking` is `adaptive`; both are left out on a model whose catalog `efforts` is empty (Haiku 4.5). Consecutive user messages (left behind by an interrupt) are merged when the request is built, so turns alternate, and the stored transcript stays append-only. The adapter fingerprints each request (system prompt, tools, each message block, and model, `thinking` and effort) and checks it against the session's last one: the same prefix, the earlier blocks unchanged, and the parameters moved only with a route change. Any other break is logged as a warning naming the session and what changed, and throws under `cacheBreaks: "throw"`, which every native test sets.
5. **The loop**, one async generator per turn behind `Stream.fromAsyncIterable`:
   1. Stream the request. Each `text_delta` becomes a `text.delta`.
   2. Commit the whole assistant message unchanged, thinking blocks included. Its text becomes an `assistant.message` item, and its usage becomes a `usage` event priced from the catalog's list prices (`listCost`) with `accessMode: "metered"`, one per request, so an interrupted turn still records what it spent.
   3. Each `tool_use` becomes a `tool.call` item. A tool that `ask`s raises `approval.requested` and waits for `respond`. Tools run one at a time; each result is a `tool.result` item, and all of them go back in one user message.
   4. Steers wait in a queue and join that message as text blocks after the tool results, which is the safe point. If the agent ends its turn with steers still queued, they go in as the next user message and the loop goes on.
   5. `end_turn` with nothing queued ends the turn with `turn.finished` `success`. `refusal`, and `max_tokens` with a `tool_use`, end it with `error`, saying why, and run none of that message's tools.
6. **Interrupts.** `Stream.onExit` aborts the turn's `AbortController`, and from then on the turn appends nothing, so a half-streamed message is never committed. The next request is built from the transcript as it stands: a `tool_use` left without a result gets an error result saying the user interrupted the turn, inserted while building, never written, so the same transcript always builds the same bytes and the cache holds. A tool that had already run when the interrupt came is reported to the agent as not run.
7. **Modes.** The turn's mode goes into its own user message as a short Verdandi note, never into the system prompt (cache rule), when it differs from the mode the session last heard, and always on the first turn after a resume or fork. `ask` and `plan` tell the agent not to change anything; `plan` asks it to call `propose_plan`, which raises `plan.requested`. Allowing the plan lets the same turn go on building. Denying it returns the feedback as the tool result. The file tools that change files (`write_file`, `edit_file`, #178) refuse in `ask`, and in `plan` until the plan is approved, with a result saying why, so a tool can't break either mode.
8. **Reroute** sets the session's model for its next request. The prompt cache is per model, so the switch writes a cold prefix, which the switch-cost gate already prices. Other models ignore the old model's thinking blocks.
9. **Task limits.** `maxCost` is checked after each request against `spentUsd` plus what the turn has spent; past it, the turn ends with `limit`. `maxTurns` counts the task's model requests: each is reported as `model.called` before it's sent, the reactor passes the task's earlier count as `spentTurns`, and a request that would pass the limit isn't sent (the same ceiling as Claude Code's, ADR 0005).
10. **The key.** verdandid reads `VERDANDI_ANTHROPIC_API_KEY` from its environment (Bun loads `.env`), else `Bun.secrets.get({ service: "verdandi", name: "anthropic-api-key" })`, which `verdandi key set anthropic` fills (read without echo, or piped in) and `verdandi key delete anthropic` empties. It deliberately doesn't read `ANTHROPIC_API_KEY`: Claude Code inherits verdandid's environment, and that variable would quietly move Claude Code turns from the subscription to metered API billing. With no key, `native` isn't registered. A key that is empty, holds whitespace or doesn't start with `sk-ant-` stops startup, naming where it is and the fix, without quoting it. A keychain that can't be read leaves `native` off, and `verdandi start` says why. The key is passed only to the SDK client, whose base URL, auth token and log level are set explicitly so nothing in the environment meant for Claude Code applies, and is never logged.
11. **Catalog.** `nativeCatalog` in `harness-native` lists `claude-haiku-4-5` (S), `claude-sonnet-5-5` (M), `claude-opus-5-5` (L) and `claude-fable-5-1` (XL): provider `anthropic`, `metered`, list prices, cache writes at 1.25× input. `catalogFor` adds it when `native` runs, the way `fakeCatalog` joins. The built-in policy names none of these models, so a task reaches native only through a pin or a project's `routing.yaml` until M4 routes across harnesses.
12. **Tests.** The fake provider in `packages/testkit` turns scripted responses into SSE through an injected `fetch`, so tests exercise the SDK's real parsing and can check that every request has the same prefix.

## Consequences

- Effort is a per-request parameter on native, so per-turn auto effort (§8.7) becomes possible there. A top-level effort change still invalidates the message cache, so auto effort (#185) keeps the top-level effort the task's and puts a turn's own in an effort-only system message before the turn's message (the per-message effort beta, `mid-conversation-output-config-2026-07-01`, on Opus 5.5, Sonnet 5.5 and Fable 5.1), which the transcript keeps like any other message and the cache check fingerprints. Haiku 4.5 has no effort levels and is sent the conversation without them.
- The native agent has Verdandi's tools (`memory_*`, `session_search`, `report_blocked`, `skill_manage`, `skills_list`, `skill_view`), `propose_plan`, its own file tools (`read_file`, `write_file`, `edit_file`, `glob`, `grep`, #178), and `terminal` (#179), which runs one approved command through verdandid's `runShell`, the runner verifiers use, injected into the adapter so the harness package never spawns a process or sees the environment. Attached images go in as image blocks, attached files by path for `read_file`. A session opened before the file tools keeps its tool list, so it sees attached files by name only, with a `notice`.
- Context and skills (#180, #181): a new session's system prompt holds the instructions and the skills index (each skill's name and description, sorted, within 18,000 characters and 150 skills, descriptions shortened before skills are left out), then the folder's first context file (`AGENTS.md`, `CLAUDE.md` or `.cursorrules`, one only, cut at 20,000 characters), cached up to there so worktrees of one project share it, then the folder, cached to the end. Each is scanned through the turn's `scan`: a flagged file is replaced by a `[BLOCKED: …]` marker and a flagged description left out, each with a `notice`. Without `scan` (a background review) neither goes in. The transcript's header keeps the prompt, so a resumed session builds the same bytes after a file changes; the change reaches the next session. `skill_view` reads a skill whole.
- Provider health and fallbacks (#188, #204, DESIGN §9.5): a request the SDK gave up on is classified (`classify` in `provider-failure.ts`) and reported as `provider.failed`, which waits for Verdandi's answer like an approval; allowed, `reroute` has moved the turn to a fallback and the request is sent there, denied, the turn fails with Verdandi's reason. The SDK's own retries stay (two, honouring `retry-after`).
- Not in this slice: `@` imports in a context file and subfolders' context files, `delegate_task` subagents (route subagents are ignored), parallel tool runs, compaction, refusal fallbacks, `keyCommand`, rotating keys, quota (a metered key has no subscription window).
- A tool call that waits inside itself (`skill_manage` waits for `skill.proposed`) holds the turn as long as an approval does; an interrupt stops the turn, though the call's own promise runs on unobserved.
- Upgrading the SDK means moving the Agent SDK's resolved peer along with it, or accepting two copies.
